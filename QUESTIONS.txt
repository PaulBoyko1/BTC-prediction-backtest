BTC PREDICTION BACKTEST — REMAINING QUESTIONS
============================================
Updated after the v0.2 requirements pass on 2026-08-23.

DECISIONS ALREADY RESOLVED
==========================

These no longer need answers unless you want to change them:

- Always show separate 1-year, 2-year and 3-year results.
- Show Kalshi and Polymarket separately, plus a venue-equity difference view.
- Default fair entry assumption: executable ask.
- Every full test also runs last-trade and midpoint sensitivity variants.
- Prominently flag unusually large ask-vs-last/midpoint differences.
- Re-entry behavior is configurable as an execution parameter.
- Exit behavior is configurable: expiry, target, target+stop, or time-before-expiry.
- BTC, prediction-market and settlement-reference factors can be mixed in one strategy.
- First branch selection only chooses the starting factor; it does not lock factor families.
- VWAP includes named bullish/bearish/reversal/continuation/support/resistance/breakthrough setups.
- Prediction-market shock + small-BTC-move (lead/lag test B) is a first-class factor combination.
- BTC source defaults to Binance + Coinbase composite, switchable to either venue.
- Prediction source is switchable between Kalshi / Polymarket / both.
- Settlement-reference data is kept separate from exchange spot.
- Kalshi and Polymarket may use different settlement references; do not silently substitute BTC spot.
- Prefer raw source timestamps for lead/lag research, then aggregate later.
- Portfolio/risk caps are customizable rather than treated as fixed recommendations.
- Advanced statistics should have plain-English explanations in the UI.
- Parameter sweep is required.
- Kalshi ↔ Polymarket discrepancy analysis has its own tab.
- Test A (price threshold), B (prediction shock while BTC barely moves), C (cross-venue discrepancy), and E (BTC technical combinations) all belong in the system.

KNOWN IMPLEMENTATION ITEMS (NOT QUESTIONS)
==========================================

- Exact configurable lookbacks (for example +8¢ in exactly 5 seconds, BTC move in exactly 5 seconds) need to be calculated from timestamp-indexed real history; the current demo rows use representative synthetic derived values.
- Historical reference-price charts must only appear when exact matching reference data exists; otherwise they should be labeled unavailable/proxy and excluded from settlement-specific conclusions.
- The venue-equity difference chart is a visualization; performance/edge metrics are always computed independently on each venue.
- Ask is the canonical primary fill assumption. Last trade and midpoint are sensitivity variants, not guaranteed executable fills.
- The synthetic demo contains a deliberately mild lead/lag pattern only to exercise UI logic. It must never be treated as evidence.
